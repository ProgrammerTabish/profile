Compliance assistant · 50 regulatory PDFs

Ask a question about banking regulation, then watch how the answer gets made.

Your question goes through the same pipeline as the self-hosted system I built for the SPG Innovation Challenge 2026: a German rewrite, hybrid keyword and vector search over 12,186 real chunks of GwG, KWG, MaRisk, DORA, DSGVO and EBA/ESMA texts, rank fusion, and an LLM that has to cite its sources.

What's real: the corpus, the BGE-M3 vectors, and the retrieval, fusion, citation checks and confidence score. All of it runs in your browser. What's simulated: the LLM. GitHub Pages can't host a 24B model, so the page builds the exact prompt and then shows how the model would answer it.

    The pipeline

    1. Ingest. 50 PDFs (3,387 pages) are parsed with Docling and cut into 12,186 chunks that never cross a § / Artikel / AT boundary, so every citation can say 01_GwG.pdf | § 10 | p. 17-18.
    2. Embed + index. BGE-M3 (1024-d) dense vectors plus BM25 sparse vectors go into Qdrant.
    3. Retrieve. Most questions are in English and most of the law is in German, so each question also gets a German query (an LLM rewrite plus an EN→DE compliance glossary). Four ranked lists, fused with weighted Reciprocal Rank Fusion, capped at 4 chunks per document.
    4. Generate. Mistral Small 3.1 24B (Ollama) or Llama 3.3 70B (vLLM), inside the bank's tenant. It must cite [n] after every statement.
    5. Verify. Citations to sources that don't exist are removed. Fewer than 2 citations triggers a retry. NOT_IN_SOURCES produces an honest refusal.
    6. Audit. Every question, source and answer is logged under its request id.

    What this page does differently

    • Same data. The texts and BGE-M3 vectors come from the repo's prebuilt rag_db. The vectors are PCA-compressed 1024 → 96 dimensions (int8), which keeps about 75% of each chunk's true top-20 neighbours.
    • Same keyword search. The tokenizer is ported line by line, so § 25h, Art. 5b and AT 4.4.2 stay single tokens. Scoring is BM25 with Qdrant's IDF.
    • Approximate question vector. Your browser can't run BGE-M3 (2.2 GB), so the question's vector is the average of its top keyword hits (pseudo-relevance feedback). The cosine search over all 12,186 real vectors is real.
    • Simulated LLM. For the evaluation-set questions, the answer text is the challenge's reference answer (its expected key points). For your own questions, it's built from the best-matching source sentences, the same deterministic stand-in the repo's test suite uses. Either way, the citations point to the chunks that were actually retrieved, and the confidence score is computed from them.
    • On the 30 in-scope evaluation questions, this browser retrieval puts an expected source document in the top 8 for 26 of 30.
